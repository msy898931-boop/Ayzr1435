
## 2026-11-20 — the 205-point "scenario" (unreachable break triggers)

⭐ **The owner got a prep alert saying "buy above 3,759.10" while gold traded
3,554.** A trigger 205 points away, priced as a full trade (entry/stop/target).
Root cause: after a one-way slide the 1h pivot list holds NO level near price, so
`_levels()` falls back to the swing extreme (`min low`/`max high` of the last 120
bars). That fallback is a real level, but `card_scenarios`/`card_news_prep`
priced it as if it were tradeable.

⭐ **My first instinct — "make the stop ATR-scaled" — was WRONG and I said so.**
bot.py:105 already records that a wider / ATR-scaled stop **tested WORSE** on the
2026 replay. And at $200 / 0.01 lots the point value is **$1**, so a 30-pt stop
is **$30 = 15% of the account**; 0.01 is the broker minimum lot, so the stop
cannot widen without risking more money. The stop was never the defect — the
unreachable trigger was.

⭐ **The fix: `SCEN_MAX_ATR` (3× the 1h ATR).** Helpers `_scen_reach`,
`_scen_is_reachable`, `_scen_far_note` sit next to `_break_levels`. A trigger
past the limit is NAMED as a watch level with its distance and ATR multiple,
never priced. Missing ATR / trigger / price ⇒ `None` ⇒ behaves exactly as
before, so a feed hiccup can't blank a scenario.

⚠️ **ONE ENGINE, MANY VIEWS — and I missed one on the first pass.** The first
commit (19ac790) guarded only the two Telegram cards. `map_payload()` prices the
same break INDEPENDENTLY (bot.py ~3128), so the page still offered the 3,759
trade while the card refused it — the exact drift the repo warns about. Second
commit (9f146e9) added `reachable` to the map payload (unpriced when False) and
taught map.html to render it, or the page would print "undefined" where the stop
goes. **When fixing a rule, grep for every producer of that number, not just the
card the owner complained about.**

- Tests **372** (364 baseline + 8 new), all green. Deployed `9f146e9`, verified
  live: `map.json` shows `long reachable False` / no stop, `short` priced.
- `/map.json` takes ~27 s on Render (full map payload) — a 25 s curl reads as
  code 000. Not a bug.
- Ruff/mypy are NOT installed in this sandbox (`No module named ruff`), so those
  two baselines could not be re-run.

## MarketDesk — two new engines: silver + bitcoin (2026-11-17)

- Owner asked for TWO buttons and TWO engines: silver and bitcoin, each an
  independent professional read (scenarios, tops/bottoms, S/R, supply/demand,
  sniping, when-to-buy/sell WITH reasons). Hard condition: **do not touch gold**.
- ⭐ **Followed the `ayzr.py` precedent, not a second copy of `bot.py`.** New
  `markets.py` imports nothing from bot.py; bot.py got two 10-line DOORS
  (`card_silver`/`card_bitcoin`) that lazy-import and return the module's text.
  bot.py diff = **+39 lines, 0 deletions** in gold logic. That is what makes
  "don't touch gold" a structural fact, not a promise.
- ⭐ **Per-asset CONTRACT is the thing that decides money, and the two assets are
  opposites.** `XAGUSD` 1 lot = 5,000 oz → 0.01 lot = 50 oz → **$50/point**;
  `BTCUSD` 1 lot = 1 coin → 0.01 lot = 0.01 → **$0.01/point**. So a sane 1.5×ATR
  stop on silver = **$47 (23.7% of $200)** = untradeable; the same on BTC =
  ~$9 = fits. The engine returns `fits=False` + the noise ratio instead of
  quoting a stop inside the noise. **I had earlier told the owner BTC was 20×
  too big for his account — that was WRONG** (confused 1 BTC with 0.01 BTC).
- ⭐ **A card that cannot be sent is a card that was not written.** `markets.py`
  caps at `MAX_CARD = 3900` because `Telegram.send` truncates at 4000. Both
  reports land ~2.4-2.5k chars.
- ⭐ **The test found a real bug**: `report()` called `snapshot()` outside any
  try, so a dead feed raised upward instead of returning a sentence. Fixed.
- **Baselines move with the tool version, not with my change.** Installed ruff
  freshly and `HEAD` bot.py alone reports **41** findings (AGENTS.md says 16),
  mypy **3** (matches). Verified by running the linters on `git show HEAD:bot.py`
  in /tmp — my change added 0 to both. `markets.py`: ruff clean, mypy clean.
