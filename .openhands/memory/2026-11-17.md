## The open bell — the desk was silent at the one moment the owner asked about

- ⭐ **The desk announced the CLOSE and never the OPEN.** `maybe_daily_report`
  fires on the observed open->closed edge; nothing mirrored it. After a 48-hour
  weekend the first thing the owner heard was a trade — or nothing. Added
  `maybe_open_bell()` + `open_bell_due()` + `open_bell_text()` in bot.py, wired
  into `desk_tick` immediately after `maybe_daily_report`. Commit `68c5412`.
- ⭐⭐ **Two flags, not one — and sharing it is a silent dead feature.**
  `maybe_daily_report` sets `was_open=True` on EVERY open cycle, so a bell that
  read `was_open` would always conclude "already open" and never ring at all.
  The bell keeps `bell_was_open`. This is the classic one-engine trap: the same
  field meaning two things in two readers. A test
  (`test_rings_even_after_the_close_report_ran`) pins it by running the close
  report first, then the bell.
- ⭐⭐ **`bell_saw_closed` — a transition must be WITNESSED, not inferred.**
  Render has no disk, so every redeploy starts with an empty `daily.json`
  while the market may already be open. Without this flag the bell re-rings on
  every deploy (the weekend announcement, four times). Verified the hazard
  empirically first (simulated unlink -> 2 bells), then fixed, then
  `test_a_lost_daily_file_does_not_ring_again`.
- ⭐ **Audience: `_desk_chats`, not `_alert_chats`.** `_alert_chats` is
  everyone allowed; `SEED_CHATS` has TWO ids (owner + one guest).
  The bell is the close report's mirror, so it follows the close report's rule
  (owner-only under `OWNER_ONLY=1`). Test pins `seen_chats == [_backup_chat()]`.
- ⭐ **`DAILY_PATH` was NOT isolated in `setUpModule`** — only in
  `DailyScheduleTest.setUp`. `maybe_daily_report` and the bell both WRITE it
  every cycle, so a suite run stamped the real `data/daily.json`. Now isolated
  module-wide alongside STICKY_PATH / WATCH_POINTS_PATH / DB_PATH.
- Suite 391 -> 398 tests, all green. `--selftest` prints the `== open_bell ==`
  card and leaves the journal at 0 trades.
- Levels checked while investigating (2026-11-21, price 3,539.14): live pivots
  res 3,585.92 / 3,595.36, sup 3,514.55 / 3,502.78. Simulated a rally: alerts
  fire at 3,588 (through 3,585.92) and 3,602 (through 3,595.36) — the broken
  2026 low area IS covered by the live pivot watch. `WATCH_LEVELS` frozen set
  and `WATCH_POINTS` defaults (3757/3770/3780) are all far ABOVE price = stale
  but harmless, since `_live_levels` carries the real ones.

## MarketDesk — the owner's last brief: his scenarios only, no rest, securing (2026-11-17)

His three asks in one message: "خلي البوت مايتداول غير عسيناريوهاتي يلي حطيتها
وبلا راحة بعد الصفقة وخلي يشتغل عتأمين وعأكتر من هدف اذا كان موجود".

- ⭐ **PLANS_ONLY ends `desk_tick` right after `plans_watch`/`_take_plan`.**
  Not a deletion: the engine still reads the tape and still feeds `map_payload`,
  the analysis card and `plan()` — he asked it to stop TRADING on its own, not
  to stop LOOKING. Every view must keep working, so a "plans only" patch that
  gutted `plan()` would have been the wrong fix. `DESK_PLANS_ONLY=0` restores
  the old desk without a revert.
- ⭐ **The rest gap is a DEFAULT, not a deletion.** `REST_MINUTES` default went
  15 → 0; the mechanism and `_rest_until()` stay, because a switch that can be
  turned back on must still work when it is. The test pins the default by
  reading bot.py for `DESK_REST_MINUTES", "0"` — a value assertion, not a source
  grep for its own sake.
- ⭐ **The ladder is per-ROW state, and `target` stays the FIRST rung.** New
  columns (`targets` JSON, `rung_hit`, `realized_usd`, `realized_r`,
  `init_stop`) arrive by an IDEMPOTENT `_migrate()` — a journal restored from
  the pinned backup carries the OLD schema, so `CREATE TABLE IF NOT EXISTS`
  alone would have left a live book without the fields. Historical rows must
  keep grading exactly as before; that is the floor the whole change sits on.
- ⭐ **`init_stop` exists because securing MOVES `stop`.** R must stay measured
  against the risk the trade was actually taken at; without it, a secured trade
  reports R against a zero denominator or a bogus one.
- ⭐ **Several rungs can fall on ONE bar, so the running totals must be LOCAL.**
  My first version re-read the row between rungs and lost the rung banked a
  moment earlier (3 rungs paid 16$ instead of 24$). Seed `banked/base_m/base_r`
  from the row once, then update them in the loop. The same bug class bit
  `_money`: the remainder's share is `(n - rung_hit)/n`, never `1/n`.
- The owner's targets are taken AS WRITTEN (`_plan_rungs`), sorted, and levels
  already behind the entry are dropped — a rung the market passed is history,
  not a target. The engine's single target is only the fallback.
- ⚠ **`_plan_open_card` must read the PLAN, not the row.** Tests pass a stub
  `{"id": 7}`; reading `_ladder_of(row)` crashed three of them. `_ladder_of`
  now also tolerates a dict with no `target`/`targets`.
